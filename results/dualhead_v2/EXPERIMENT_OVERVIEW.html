Dual-Head Function Naming

A reader's guide to the experiments: what the task is, why the evaluation was rebuilt, how the two heads and the router work, and how the final system compares with SymGen and BLens when every system is trained on the same data.

test = 268,178 functions · 50 packagesmetric v2 sub-token F1all baselines retrained on our train tiersource: results/dualhead_v2/FINAL_TABLES.md

1The problem

When a binary is stripped, its symbol table is removed and every internal function becomes an anonymous address (sub_4a3f20). Reverse engineers, vulnerability analysts and decompiler users spend most of their time re-deriving what those functions are. The task is to predict the original developer-given name — ngx_http_upstream_init_keepalive_peer, mbedtls_ssl_write_fragment — from the stripped code alone.

A name is scored as a bag of sub-tokens (ngx · http · upstream · init · keepalive · peer). Predicting ngx_http_upstream_init_peer earns partial credit (F1 = 0.91); predicting nothing, or something unrelated, earns 0. Exact match (EM) is reported alongside F1 but is a much harsher signal.

Two things make this hard. First, most functions in a fresh project have names the model has never seen — in our test tier 87.5 % of functions carry a novel name. Second, the same source compiled at different optimisation levels, or slightly different versions of the same project, produce near-identical binaries: a system can look excellent by memorising those and still fail on genuinely new code. Separating the two situations is the spine of everything below.

2Why we restarted (August 2026)

The spring system (submitted to CCS as "HyDRA", rejected on generalisability grounds) reported a cross-project F1 of 0.74. An audit on 18 Aug showed why the reviewers were right to be suspicious: 89.5 % of the old test functions were token-identical to a training function, because the split was by binary rather than by package, and the corpus contained many versions and optimisation levels of the same projects. The 0.74 was essentially the "seen-name" stratum — functions whose name was already in the training set.

Rather than patch the split, the project was reset on 17 Aug: the binary lifter defects were fixed (B1–B9, plus an eh_frame-based function rooter that finds 99 % of functions where the stock BAP pass found 71 %), the corpus was rebuilt, and an honest evaluation protocol was agreed on 23 Aug. Every number on this page comes from that protocol.

Honest baseline under the new protocol: the unchanged CCS-era decoder scores test micro-F1 0.086 (macro 0.308). Seen-name functions: 0.526. Novel-name functions: 0.016. That gap — not the 0.74 — is the actual starting point of this work.

3Evaluation protocol (dataset v2, split policy v3, metric v2)

Corpus

120 open-source C/C++ packages, 1,890 binaries, compiled at O0–O3 with GCC, lifted with BAP (patched) and independently decompiled with Ghidra. Ground-truth names come from the unstripped twin of each binary.

Three package-disjoint tiers

train · 190,151 functions997 binaries. Deduplicated on (token-hash, name) so a function is learned once.
val · 10,617 functions10 whole packages never in train. Used for every model-selection and router-fitting decision.
test · 268,178 functions611 binaries, 50 packages never in train. Two hygiene drops: functions whose body is token-identical to a training function (81,988) and exported symbols recoverable from the dynamic symbol table (12,746).

Regimes and strata

Test packages are tagged by how close they are to the training corpus. The grouping unit is the package family (name overlap ≥ 0.35 on non-ubiquitous names), so a version pair like gzip/gzip2 lands in the same family.

NCT — near-clone transfer · 23 packages · 44,510 fnsFamily-linked to a training package (e.g. nginx118 vs the nginx forks in train, version pairs of GNU tools). Tests robustness to versions and compilers.
FT — far transfer · 27 packages · 223,158 fnsNo family relation to train (bdb, icu, mbedtls, libsodium, mutt, fossil…). Tests genuine generalisation. bdb + icu alone are 44 % of the test tier — hence macro.
seen-name · 32,996 fnsThe ground-truth name occurs somewhere in the training tier (often shared gnulib code).
novel-name · 234,672 fnsThe name is absent from train. The only way to score here is to compose it from evidence.

Metric

Metric v2: names are C++-demangled, templates and argument lists stripped, split on underscores and camelCase, lower-cased; sub-token precision/recall/F1 per function. Micro averages over functions (dominated by the big packages); macro averages the per-package means (every package counts once). Both are always reported. Selective F1 @ k % is the F1 on the k % of functions the system is most confident about — the number an analyst sees if the tool only speaks when sure.

4The two input representations

The whole redesign rests on giving the model two different views of a function.

View A · lifted IR (BAP)

Instruction-type tokens (~2.3K semantic classes: CALL_malloc, MEM_WRITE_ARG_64, COND_BRANCH_ZF…) per basic block → 4-layer Transformer block encoder → 3-layer graph attention over the control-flow graph → attention pooling → 1024-d function embedding. Gated fusion adds external (PLT) calls, the token signatures of up to five callees and five callers, and — new in this cycle (A1a) — the identifier-shaped strings the function references in .rodata (log/assert messages that literally contain names).

34 M parameters · milliseconds per function
View B · decompiled text (Ghidra)

The stripped binary is decompiled to C-like pseudocode with all names masked; the text (≤ 1,024 tokens, covering 82 % of functions) is fed to a code language model. This is the representation the strongest published system (SymGen) uses, at 34 B parameters; we use it at 220 M.

CodeT5+ 220 M · Ghidra decompilation required

View A is cheap, compiler-aware and excellent at recognising code it has seen a variant of. View B carries the surface cues (constants, string literals, call shapes, control structure in readable form) that a language model can turn into a plausible new name. Neither view alone covers both regimes — that is the dual-head thesis, and section 6 measures it.

5Heads and router

  • D · BAP decoderA GRU sequence decoder over the View-A embedding — the original architecture, kept as the ablation reference. Test 0.086 → 0.100 / 0.339 with the string channel (A1a).Chosen by the router 0.5 % of the time in a 3-head union; dropped from the final system.
  • R · BAP retrievalk-nearest-neighbour lookup of the View-A embedding against all 190K training functions; the top neighbour's name is the prediction (re-ranked by string overlap). Trained with a name-aware contrastive objective (C1): the InfoNCE target for a pair is soft, proportional to the sub-token F1 between their names, with cross-package pairs up-weighted and hard negatives mined from the previous encoder's neighbours. Test 0.127 / 0.385; NCT 0.564, novel-name 0.035.Owns the near-clone regime. Almost blind on novel names by construction — it can only return names that exist.
  • A4 · generationCodeT5+ 220 M fine-tuned on the Ghidra pseudocode of the 190K training functions (names masked exactly as SymGen's builder does). Test 0.185 / 0.368; FT 0.121; novel-name 0.123 — five times the retrieval head.Two seeds agree within ±0.001. A second run with the public SymGen corpus added won on val (0.237 vs 0.200) but lost on test (−0.007); reported, not adopted.
  • RouterA gradient-boosted classifier on 11 per-function features — retrieval similarity and margin, external-call and string Jaccard to the neighbour, decoder and generator confidences, sizes — fit on val only. It picks R or A4 for each function (82 % right on the 31.6 % of functions where the heads disagree) and its score doubles as the abstention signal for selective prediction.Simpler thresholds on retrieval similarity alone reach 0.196–0.198; the learned router adds +0.007 and, more importantly, a calibrated confidence.

7Against the published baselines — same training data, same functions

Two systems define the state of the art: SymGen (NDSS 2025; CodeLlama-34B with a LoRA adapter, reads Ghidra decompilation) and BLens (CCS 2025; CLAP + PalmTree embeddings, a CoCa-style contrastive pre-training and a transformer name decoder with confidence-thresholded abstention). Both were retrained on our 190,151-function training tier with their published recipes (SymGen: 1 epoch, 1,485 steps on 4×A100; BLens: 80 + 80 epochs, best epoch by its own validation) and scored with metric v2 on exactly the same functions as our heads. The earlier comparison, where SymGen's adapter had been trained on its own corpus that overlaps nine of our test packages, is retired.

Caveats we will state. BLens abstains on 46.0 % of functions (its confidence threshold; an empty answer scores 0). BLens shows the same recognizer signature as every other system: 0.38 on seen names, 0.013 on novel ones.

7c · External benchmark — SymGen's own held-out packages

Five packages from SymGen's public corpus that are in neither our train tier nor our test tier (gmp, libpng, libmicrohttpd, poke, libredwg; 9,991 scorable functions). Our generation head scores micro 0.223 / macro 0.189 / EM 16.1 % (0.233 when the public SymGen corpus is added to its training data).

9Findings the paper will rest on

  1. Regime specialisation is real and cross-system. Retrieval over lifted IR owns near-clone code (0.744 vs SymGen 0.260 on the same functions); a decompilation language model owns far transfer and novel names (0.123 vs 0.035). No single system, including a 34 B one, holds both.
  2. The union is the contribution, and it is measurable inside one system. R ∪ A4 with a learned router: 0.205 / 0.438, oracle 0.224 / 0.471. The router closes 91 % of the head-choice gap.
  3. Calibrated abstention is the practical headline. Selective F1 0.94 / 0.88 / 0.69 at 5 / 10 / 20 % coverage; expected calibration error ≈ 0.005. An analyst can be given the confident 10 % with near-usable precision.
  4. Everyone is a recognizer on novel names. Seen-name vs novel-name: ours 0.796 vs 0.121, BLens 0.382 vs 0.013, SymGen's novel-name F1 on the NCT sample 0.267. Exact match on novel names is ≤ 2 % for every system. The paper frames far transfer as a coverage boundary, not a solved problem.
  5. Fair baselines change nothing about the ordering. Retraining SymGen and BLens on our tier moved SymGen by +0.004 / +0.025 and left BLens at 0.059 overall.
  6. Cost. Retrieval-only is 34 M parameters, BAP-only, milliseconds per function. The full union adds a 220 M model and Ghidra decompilation; SymGen needs a 34 B model and ~2.6 s per function on an 80 GB GPU.

Reproducibility. Two seeds of the generation head agree within ±0.001 on every column; the retrieval encoder's λ sweep (0.3 vs 1.0) is a wash at the system level (±0.002).
